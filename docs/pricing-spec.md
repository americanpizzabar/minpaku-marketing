# 機能要件・設計仕様書：競合稼働連動型ダイナミックプライシング・モジュール

> 利用者から提供された仕様書の原文 (実装の受け入れ基準)。

本仕様書は、山中湖エリアにおける高価格帯・一棟貸しヴィラ（Lumina Fuji Residence Yamanakako想定帯）の収益最大化を目的とし、周辺競合の予約状況および予約消化ペース（平日・週末別）に応じた最適販売価格を自動算出・可視化するための機能仕様を定義します。

## 1. システム概要と目的
目的: 勘や固定シーズン料金に依存せず、向こう60日間の市場需給変化（競合の残室数と消化スピード）に基づき、機会損失（売り惜しみ）と稼働割れ（高値放置）を防ぐ最適推奨価格（ADR）を日次で導出する。

主要アプローチ:
- ターゲット物件の競合集合（CompSet）を「同等価格帯」「一棟貸し」「特定収容人数」でフィルタリング。
- 予約日までのリードタイム、平日・週末（金土・休前日）の特性差を分離して分析。
- 競合の占有率（Occupancy Rate）および価格改定履歴から、日別の推奨宿泊料金と調整幅を提示。

## 2. 競合セット（CompSet）抽出・フィルタリング仕様
山中湖エリア全域の民泊データから、自社と同セグメントの物件を動的にクラスタリングします。

| 抽出パラメータ | 条件・閾値 | 備考 |
|---|---|---|
| 対象エリア | 山中湖畔から半径 5〜7km 圏内（平野・旭日丘・山中等） | 車移動前提の同商圏 |
| 物件タイプ | 一棟貸し（Entire home/villa） | ホテル・相部屋は除外 |
| 想定客室単価（ADR） | 自社基準価格の ±30% 範囲 | ハイエンド〜プレミアム帯 |
| 最大収容人数 | 6名〜10名規模（同等定員レンジ） | グループ・ファミリー層を合致 |
| レビュー評価 | Rating 4.7以上 / レビュー件数 5件以上 | 稼働実態のある稼働競合に限定 |

## 3. 分析・プライシング算出ロジック
### 3.1. 期間・セグメント定義
分析対象期間:
- 直近実績（過去14日間）：直前予約の動向確認
- 将来予測（当日 〜 60日先）：プライシング対象期間

日別属性（Day Type）の厳格分離:
- 平日（Weekday）: 日曜日〜木曜日宿泊（祝前日を除く）
- 週末・ハイバリュー日（Weekend/Holiday）: 金曜日・土曜日・祝前日、特定連休

### 3.2. 稼働進捗（Booking Pace）の指標化
各日付 t（0 ≤ t ≤ 60）における競合集合の予約状況を以下の指標でトラッキングします。

- 競合占有率（CompSet Occupancy Rate: Occ_t）: Occ_t = 予約済競合室数 / 有効競合総室数 × 100 (%)
- 競合平均販売価格（CompSet Mean ADR: CompADR_t）: 空室として残っている競合の現在設定価格の中央値またはトリム平均（外れ値除外）。
- 予約消化ペース（Pace Index: PI_t）: 直近7日間における該当日の占有率増加スピード（ΔOcc_t / Δ7days）。

### 3.3. 最適推奨価格（Recommended Price）の算出アルゴリズム
基本式は自社の基準価格（Base Price: P_base）に、日別属性ごとの市場需給係数を掛け合わせて算出します。

| 補正係数 | 名称 | 判定基準と補正ロジック |
|---|---|---|
| α_t | 競合占有率係数 | ・Occ_t ≥ 80%: ＋15%〜＋25%（市場在庫払底による強気設定）<br>・50% ≤ Occ_t < 80%: ＋5%〜＋10%<br>・Occ_t < 30% かつ t ≤ 14: −10%〜−20%（直前需給低迷による集客優先） |
| β_t | 消化ペース係数 | ・直近3〜7日で競合の予約が急増している場合（イベント・需要集中）: ＋5%〜＋15%<br>・競合の予約進捗が停滞している場合: 0%〜−5% |
| γ_t | リードタイム係数 | ・t ≤ 7（直前7日以内の未稼働）: 日数経過に応じて段階的ディスカウント（平日は最大−25%、週末は最大−10%）<br>・t ≥ 45（早期予約枠）: 早期確約ディスカウント（−5%）またはハイシーズン先行高値 |

ガードレール制約（Floor & Ceiling Price）:
- ブランド毀損および清掃・リネン等の限界費用割れを防ぐため、最低許容価格（Price Floor）を設定（平日下限：例 60,000円、週末下限：例 90,000円）。
- エリア受容上限を超える異常値を抑える最高上限価格（Price Ceiling）を設定。

## 4. UI / ダッシュボード設計仕様
### 4.1. 画面構成
- サマリーKPIカード（向こう60日全体）
  - 平日平均競合占有率 vs 週末平均競合占有率
  - 推奨価格追従時の想定売上シミュレーション
  - 直近7日間で予約急増した「要注意日（Spike Dates）」バッジ
- 60日タイムライン・ヒートマップ（メインビュー）
  - 横軸：日付（60日分、曜日付き）
  - 行1：自社ステータス（予約済 / 空室 / 現在価格 / 推奨価格 / 乖離率）
  - 行2：平日/週末区分タグ
  - 行3：競合予約率ヒートマップ（0%〜100%をグラデーション表示）
  - 行4：競合残室数＆平均価格推移
- 平日 vs 週末 比較ディープダイブ・チャート
  - 平日と週末を左右に分割した散布図・折れ線グラフ。
  - リードタイム（横軸）ごとの「競合の平均予約確定タイミング」を可視化（例：週末は30日前に80%埋まるが、平日は7日前に急増するなど）。
- 価格ワンクリック反映・エクスポート
  - 「推奨価格を一括適用（CSVエクスポート または OTA連携用フォーマット出力）」。

## 6. バッチ処理・データパイプライン
```
[外部データソース: AirROI / Apify / OTA Scraper]
                     │  (日次 午前2:00 定期取得)
                     ▼
       [Raw JSON スナップショット保存]
                     ▼
    [CompSet 抽出 & 平日/週末 タグ付与]
                     ▼
   [指標集計: 占有率・消化スピード(Pace)]
                     ▼
  [プライシングアルゴリズム適用 (3.3)]
                     ▼
 [Turso DB: pricing_recommendations 更新]
                     ▼
     [フロントエンド UI への即時反映]
```
- データ取得（午前2:00）: 向こう60日分×特定CompSetの空室カレンダー・価格を取得。
- 差分検知（午前2:30）: 前日スナップショットとの突合を行い、昨日新たに予約が入った日付（Pace変化）を特定。
- リコメンド生成（午前2:45）: 平日・週末別の閾値に基づき、向こう60日分の推奨価格テーブルを全更新。
- アラート通知（午前7:00）: 週末で競合残室が3室以下になった日や、直近7日で平日稼働率が跳ねた日が存在する場合、管理者へ通知。

## 7. 実装ステップ
- Phase 1: 指標集計クエリの実装 — 既存の取得データから、指定日付ごとの「平日/週末フラグ」「CompSet占有率」「競合中央価格」を返すSQLビュー/エンドポイントを構築。
- Phase 2: ルールベース算出エンジンの実装 — 式（3.3）に基づくパラメータ調整可能なプライシング関数の作成（係数 α, β, γ の初期値チューニング）。
- Phase 3: ダッシュボードUIへの平日/週末別チャート追加 — 60日ヒートマップと、自社価格と推奨価格の乖離がひと目でわかるインターフェースの統合。
